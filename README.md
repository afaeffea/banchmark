# Бенчмарки: STT/TTS и tool-calling

Два независимых инструмента для сравнения провайдеров:

1. **`stt_tts_bench/`** — скорость и качество распознавания и синтеза речи. Сейчас настроен
   один провайдер, **Yandex SpeechKit**; каркас рассчитан на сравнение нескольких.
2. **`toolcalling_bench/`** — поддержка и надёжность tool-calling у текстовых моделей:
   **qwen, glm, mistral, deepseek, minimax**.

## Установка

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Откройте `.env` и заполните нужные ключи (можно заполнить не все сразу — бенчмарки
просто пропустят провайдеров без ключей и выведут об этом предупреждение).

> Реальные ключи держите только в `.env` — он в `.gitignore`. `.env.example` не игнорируется
> и попадёт в репозиторий, поэтому в нём должны оставаться пустые заглушки.

## Веб-панель

Всё нижеописанное можно делать из браузера, не трогая файлы руками:

```powershell
python -m webui.server      # http://127.0.0.1:8765
```

Пять вкладок: **Прогон** (выбор бенчмарка, моделей и параметров + живой лог),
**Модели** (редактор `models.yaml` с массовым переключением base_url), **Креды**
(редактор `.env` со скрытыми значениями), **Прослушивание** (плееры с записями и расшифровками),
**Логи и результаты** (история прогонов и просмотр CSV).

Локально панель слушает только `127.0.0.1` — она показывает и редактирует содержимое `.env`.
Ничего не захардкожено: список бенчмарков берётся из `webui/benchmarks.yaml`, модели —
из `toolcalling_bench/models.yaml`, переменные — из `.env`.

## Деплой на Railway

У панели два режима, переключение автоматическое по наличию `DATABASE_URL`:

| | локально | Railway |
|---|---|---|
| адрес | только `127.0.0.1` | `0.0.0.0:$PORT`, публичный URL |
| хранение | файлы в `results/` | Postgres (диск контейнера эфемерный) |
| креды | видны и редактируются | из переменных Railway, в панели только «задано / не задано» |
| защита | не нужна | просмотр открыт, изменения — по паролю |

Просмотр логов, результатов и записей открыт всем, у кого есть ссылка. Всё, что тратит
деньги или меняет конфигурацию — запуск прогона, правка моделей, загрузка записей, чтение
кредов — требует входа по `PANEL_PASSWORD`.

**Значения ключей наружу не отдаются никогда.** В облаке `/api/env` возвращает только имена
переменных и факт, что они заданы.

### Порядок действий

```powershell
npm i -g @railway/cli      # CLI не установлен в проекте
railway login              # откроет браузер — шаг делаете вы
railway init               # создать проект
railway add --database postgres      # DATABASE_URL появится автоматически
```

Затем задайте переменные — в веб-консоли Railway или командой:

```powershell
railway variables --set PANEL_PASSWORD=<надёжный пароль>
railway variables --set PANEL_SECRET=<длинная случайная строка>
railway variables --set TOKENROUTER_API_KEY=<ключ>
railway variables --set YANDEX_API_KEY=<ключ> --set YANDEX_FOLDER_ID=<id>
railway variables --set HF_TOKEN=<токен>
```

`PANEL_SECRET` подписывает cookie сессии: без него он генерируется заново при каждом
рестарте и все входы слетают.

```powershell
railway up                 # сборка по Dockerfile и деплой
railway domain             # выдать публичный URL
```

Схема БД создаётся сама при первом старте, миграции запускать не нужно.

### Чего в облаке не будет

- **Записи с микрофона** нужно наговорить заново: старые лежат в локальном `data/`.
  Railway отдаёт HTTPS, так что микрофон в браузере работает.
- **Кэш датасета** скачается заново при первом прогоне (несколько секунд).
- **Прошлые локальные результаты** не переносятся — так и было задумано.

## 1. STT/TTS бенчмарк

Источник тестовых данных задаётся в [stt_tts_bench/dataset.yaml](stt_tts_bench/dataset.yaml) —
по умолчанию `bond005/rulibrispeech`. Датасет не должен принадлежать никому из сравниваемых
вендоров, иначе у него будет фора. Строки берутся через datasets-server API, аудио качается пофайлово и
кэшируется в `data/cache/`: первый запуск — секунды, повторные — мгновенно.

```powershell
python -m stt_tts_bench.run_stt --n 20   # распознавание речи: WER/CER + латентность
python -m stt_tts_bench.run_tts --n 10   # синтез речи: латентность + разборчивость + сэмплы для прослушивания
python -m stt_tts_bench.run_stt --refresh        # перекачать записи, игнорируя кэш
python -m stt_tts_bench.run_stt --source mic     # на своих записях с микрофона (см. ниже)
```

Кэш инкрементальный: `--n 20` после `--n 5` докачает только недостающие 15, а не всё заново.

### Свой голос вместо корпуса

Вкладка **«Микрофон»** в панели: записываете фразу, вписываете, что именно сказали — это
становится эталоном. Одна запись даёт сразу два теста:

- **аудио уходит в STT** — расшифровки движков сверяются с вашим эталоном (WER/CER);
- **тот же текст уходит в TTS** — обе системы синтезируют вашу фразу.

Дальше на вкладке «Прогон» выбираете источник «Мои записи с микрофона» (или флаг
`--source mic`). Это важно, потому что корпус — чистая студийная начитка: WER на нём
ничего не говорит о том, как движок справится с вашим микрофоном, акцентом и фоновым шумом.

Браузер сам пересобирает запись в WAV 16 кГц моно — тот же формат, в котором провайдеры
получают записи из корпуса, так что сравнение честное. Записи лежат в `data/mic_samples/`
(каталог в `.gitignore`).

Что считается автоматически:
- **STT**: WER/CER относительно эталонной расшифровки, латентность (mean/median/p95).
- **TTS**: латентность синтеза, плюс **WER разборчивости** — синтезированное аудио
  прогоняется через STT и сравнивается с исходным текстом. Проверять нужно движками **всех**
  доступных провайдеров, а не только «родного»: иначе вендор получает фору на собственном
  декодере (см. предупреждение ниже).

### Прослушивание

Оба прогона раскладывают записи рядом с результатами, так что цифры можно проверить на слух:

- `results/stt_samples_<timestamp>/` — **исходные аудио**, которые скармливались движкам,
  плюс `manifest.json` с эталоном и расшифровкой каждого провайдера;
- `results/tts_samples_<timestamp>/<provider>/` — **синтезированные** записи и манифест
  с тем, что расслышали в них STT-движки;
- `results/tts_manual_review_<timestamp>.csv` — лист с колонками `naturalness_1to5`
  и `clarity_1to5`: WER ловит разборчивость, но слеп к естественности интонации.

Удобнее всего слушать на вкладке **«Прослушивание»** в панели: там плеер, эталонный текст,
что услышал каждый движок и WER цветной плашкой. Файлы обычные `.wav` — открываются и любым
проигрывателем прямо из папки.

### Заметки по провайдерам

**Yandex**: REST API v1 (`stt:recognize` / `tts:synthesize`) — синхронный, без стриминга;
для бенчмарка на коротких фразах этого достаточно (лимит STT v1: ≤30с/≤1МБ).

**Добавить второго провайдера** — это новый класс в `stt_tts_bench/providers/`, наследник
`STTProvider` или `TTSProvider` из `base.py`, плюс строчка в `build_providers()`
(и в `build_stt_checkers()`, если у него есть распознавание). Все провайдеры обмениваются
сырым PCM16 mono, так что конвертировать форматы не нужно.

> **Пока провайдер один, метрика разборчивости TTS занижена.** Синтез Яндекса проверяется
> распознаванием Яндекса: общий фронтенд и одинаковые акустические соглашения дают фору,
> и WER выходит оптимистичнее реального. Прогон об этом предупреждает. Честной цифра станет,
> когда появится второй независимый STT — до тех пор опирайтесь на ручную оценку на слух.

## 2. Tool-calling бенчмарк

Все пять моделей вызываются через их "родные" OpenAI-совместимые эндпоинты (единый `openai`-клиент,
просто разный `base_url`) — конфиг в `toolcalling_bench/models.yaml`.

```powershell
python -m toolcalling_bench.selftest                    # оффлайн-проверка чекеров, без ключей и без трат
python -m toolcalling_bench.run --suite hard            # basic | hard | all
python -m toolcalling_bench.run --suite hard --models qwen,deepseek
```

По умолчанию все пять моделей ходят через шлюз-роутер (`base_url: https://api.tokenrouter.com/v1`,
ключ из `TOKENROUTER_API_KEY`), а `model` — это slug вида `provider/model`. Любой из этих
параметров меняется на вкладке «Модели» или прямо в `toolcalling_bench/models.yaml`:
чтобы перевести модель на прямой API вендора, достаточно указать её `base_url`
(например `https://api.deepseek.com/v1`) и `api_key_env` (`DEEPSEEK_API_KEY`).

Список доступных моделей роутера можно посмотреть так:

```powershell
curl https://api.tokenrouter.com/v1/models -H "Authorization: Bearer <ключ>"
```

### Ограничение частоты

Секция `rate_limit` в `models.yaml` (и поля на вкладке «Модели») задаёт паузу между запросами
и число повторов при 429. Лимит **общий на весь прогон**, а не на модель: при работе через роутер
он считается по ключу. Пауза троттлинга не входит в замер латентности, иначе метрика показывала бы
собственное ожидание вместо скорости модели.

Прогон из 5 моделей — это ~37 запросов, при лимите 9 запр./мин он занимает около 4 минут.
Если бенчмарк валится пачкой `429` — снизьте `requests_per_minute`.

**Если получаете `model_not_found`/404** — поправьте поле `model`, slug'и моделей быстро устаревают.

### Базовый набор — 7 задач, `toolcalling_bench/tasks.py`
Проверяет, что тулкол работает в принципе. Его проходят все модели, поэтому для сравнения
он бесполезен — только для отладки подключения.

| Задача | Что проверяет |
|---|---|
| `weather_single` | базовый единичный вызов с одним строковым аргументом |
| `calc_arithmetic` | несколько типизированных аргументов (числа + enum) |
| `currency_conversion` | три обязательных аргумента разных типов |
| `no_tool_needed` | ложные срабатывания — инструмент доступен, но для small-talk не нужен |
| `enum_strict` | точное соответствие enum-значению + составной аргумент даты |
| `parallel_calls` | несколько вызовов одного инструмента за один ход |
| `multi_turn_followup` | результат инструмента должен попасть в финальный ответ |

### Тяжёлый набор — 9 задач, `toolcalling_bench/tasks_hard.py`
Вот он модели уже различает.

| Задача | Что проверяет |
|---|---|
| `tool_selection_among_many` | выбор одного нужного инструмента из двенадцати, среди которых есть похожие |
| `nested_object_args` | вложенный объект в аргументах + массив участников |
| `array_of_objects` | массив из трёх позиций с числовыми полями и строгим enum валюты |
| `chain_find_then_block` | цепочка: id из результата первого вызова обязан уйти во второй |
| `missing_info_must_ask` | **обязательных данных нет** — надо переспросить, а не выдумать аргументы |
| `relative_date_and_time` | «послезавтра в половине восьмого вечера» → 2026-09-17, 19:30 |
| `tool_error_handling` | инструмент вернул ошибку — нельзя делать вид, что всё получилось |
| `parallel_three_cities` | три параллельных вызова с разными аргументами |
| `enum_unit_mapping` | разговорная формулировка → значения enum + дробное число |

Добавить задачу — это объект `Task` со списком шагов; общие типы и хелперы в `task_types.py`.
**После правок чекеров запускайте `python -m toolcalling_bench.selftest`** — он оффлайновый,
гоняет ~39 синтетических случаев и проверяет, что верные ответы проходят, а типовые ошибки
отклоняются.

Для каждой модели/задачи фиксируются: прошла ли проверка, валиден ли JSON аргументов,
латентность запроса, текст ошибки API (если был сбой аутентификации/сети/модели).

Результаты обоих бенчмарков сохраняются в `results/*.csv` (не попадает в git).

## Структура проекта

```
common/env.py              — .env, общие пути
stt_tts_bench/
  providers/yandex.py        — клиент STT/TTS
  dataset.py                — загрузка google/fleurs (ru_ru)
  metrics.py                 — WER/CER, статистика латентности
  audio_utils.py              — PCM16 <-> WAV
  run_stt.py / run_tts.py     — CLI-раннеры
toolcalling_bench/
  models.yaml                — реестр моделей (id, base_url, env-переменная ключа)
  providers.py                 — фабрика openai.Client по конфигу
  tasks.py                      — 7 тестовых задач + чекеры
  evaluator.py                   — прогон одной задачи через одну модель
  run.py                          — CLI-раннер
webui/
  benchmarks.yaml             — реестр бенчмарков, из него строится форма запуска
  server.py                     — Flask-сервер (API + запуск подпроцессов)
  index.html                     — одностраничная панель (без сборки и зависимостей)
```

# CLAUDE.md

Бенчмарки для сравнения провайдеров: **STT/TTS** (сейчас настроен только Yandex SpeechKit) и
**tool-calling** текстовых моделей (qwen / glm / mistral / deepseek / minimax через роутер).
Плюс локальная веб-панель для запуска и просмотра результатов.

## Команды

Всё запускается **из корня проекта** и **через `python -m`** — модули используют относительные
импорты и упадут при запуске файлом напрямую.

```powershell
.venv\Scripts\activate

python -m webui.server                        # панель: http://127.0.0.1:8765
python -m toolcalling_bench.selftest          # оффлайн-проверка чекеров, без ключей и денег
python -m toolcalling_bench.run --suite hard  # basic | hard | all; --models qwen,deepseek
python -m stt_tts_bench.run_stt --n 20
python -m stt_tts_bench.run_tts --n 10
```

Виртуальное окружение — `.venv` в корне. На Windows для скриптов с кириллицей в выводе нужен
`python -X utf8`, иначе консоль ломает кодировку.

## Где что настраивается

Хардкода в коде быть не должно — три конфигурационные поверхности:

| Файл | Что задаёт |
|---|---|
| `.env` | реальные креды (в `.gitignore`) |
| `toolcalling_bench/models.yaml` | модели: `model`, `base_url`, `api_key_env` + `rate_limit` |
| `webui/benchmarks.yaml` | какие бенчмарки показывает панель и какие у них аргументы |

Всё это редактируется из панели. Добавить бенчмарк в панель = добавить запись в
`benchmarks.yaml`, код трогать не нужно.

## Два режима панели

Переключение по наличию `DATABASE_URL`, третьего варианта нет:

- **локально** — `127.0.0.1`, файлы в `results/`, креды из `.env` редактируются из панели,
  пароль не нужен (снаружи не достучаться);
- **облако (Railway)** — `0.0.0.0:$PORT`, логи и аудио в Postgres, креды из переменных
  окружения и только для чтения, изменения за `PANEL_PASSWORD`.

**Значения кредов наружу не отдаются никогда.** В облаке `/api/env` возвращает `name` + `is_set`,
и `PUT /api/env` отвечает 403. Если будете трогать этот эндпоинт — не сломайте это: панель
публична, и утечка значения = утечка ключа. Разделение ролей такое: открыто на просмотр —
логи, результаты, аудио, live-лог; под паролем — запуск прогона, правка `models.yaml`,
загрузка и удаление записей, чтение кредов.

**Бенчмарки про хранилище не знают.** Они как и раньше пишут файлы, а сервер после завершения
прогона забирает появившееся в базу (`storage.py`, `ingest_run`) и чистит с диска. Какие файлы
принадлежат прогону, определяется снимком каталога до старта — так не нужно синхронизировать
имена с таймстампами раннеров. `--source mic` наоборот: перед запуском записи выкладываются
из базы на диск (`prepare_mic_for_run`), потому что раннер читает их файлами.

**Воркер gunicorn строго один.** Состояние текущего прогона — подпроцесс и накопленный лог —
живёт в памяти процесса; при нескольких воркерах запросы попадали бы в разные копии и панель
показывала бы то пустой лог, то чужой. Параллелизм даётся потоками.

## Что легко сломать

**Slug модели ≠ API-ключ.** `model: qwen/qwen3.8-max` живёт в `models.yaml`; в `*_API_KEY`
идёт только ключ.

**Панель не перезапускается сама.** Flask без reloader: после правок `webui/server.py`
процесс надо убить и поднять заново. Код самих бенчмарков подхватывается автоматически —
они запускаются подпроцессами и читают `.env` заново на каждом прогоне.

**Лимит роутера — 10 запросов в минуту.** `rate_limit` в `models.yaml` держит паузу между
запросами и повторяет при 429. Пауза троттлинга намеренно **не входит** в замер латентности:
иначе метрика показывала бы собственное ожидание, а не скорость модели. Если пошли пачки 429 —
снижайте `requests_per_minute`, а не увеличивайте повторы.

**Библиотека `datasets` намеренно не используется.** У многих аудио-датасетов parquet упакован
гигантскими row-group без индекса страниц: ради одной строки качается весь шард. У `google/fleurs`
это 559 МБ на каждый запуск, с обрывами соединения, и datasets-server на нём тоже отдаёт
«Scan size limit exceeded». Плюс `datasets>=4` декодирует аудио только через `torchcodec`
(тянет torch). Вместо этого строки берутся через datasets-server API, а аудио качается
пофайлово и кэшируется в `data/cache/`. Не возвращайте `datasets` в зависимости.

**Новый датасет проверяйте на доступность строк** до того, как прописывать в `dataset.yaml`:
`https://datasets-server.huggingface.co/rows?dataset=<имя>&config=<конфиг>&split=<сплит>&offset=0&length=2`.
Ответ «Scan size limit exceeded» — датасет не годится.

**Датасет должен быть нейтрален к вендорам.** Сейчас это `bond005/rulibrispeech`. Нельзя брать
корпус, принадлежащий кому-то из сравниваемых провайдеров (например `sberdevices_golos_10h_crowd`
— корпус Сбера): вендор мог на нём обучаться, и он получит фору.

**Клипы бывают длиннее лимитов синхронных API** (Yandex STT v1 — 30с/1 МБ). Отсюда
`max_duration_s` в `dataset.yaml`; убирать нельзя.

**STT-провайдеры обмениваются сырым PCM16 mono без контейнера.** Оба API принимают его с
частотой, объявленной снаружи (Яндекс — query-параметром, Сбер — в `Content-Type`). Так обоим
достаётся побайтово одинаковый вход; заворачивать в WAV не нужно.

**SaluteSpeech удалён из проекта — не возвращайте его.** Сбер закрыл подключение новых
клиентов с 15 июля 2026 года и прекратил Freemium для физлиц, так что получить scope
`SALUTE_SPEECH_*` теперь невозможно (ключи GigaChat дают только `GIGACHAT_API_*` и на речь
не подходят). Речевые функции Сбера переехали в GigaChat Audio — если понадобится сторона
Сбера, это отдельный клиент к GigaChat API, а не воскрешённый `salute.py`.

## Устройство бенчмарка tool-calling

Задача (`task_types.py`) — это диалог из **шагов**. У шага есть чекер `(вызовы, текст) → вердикт`
и необязательный `tool_result`: если он задан, ответ модели и результат инструмента
подклеиваются в историю и диалог идёт дальше. Одной моделью описываются и одиночный вызов,
и цепочка зависимых вызовов, и реакция на ошибку инструмента.

- `tasks.py` — базовый набор (7 задач): проверяет, что тулкол работает в принципе. Его проходят все.
- `tasks_hard.py` — тяжёлый (9 задач): выбор инструмента из двенадцати, вложенные объекты,
  массивы, цепочка вызовов, ошибка инструмента, относительные даты и — главное — отказ
  вызывать инструмент, когда обязательных данных нет.
- `suites.py` — реестр наборов.

Чекеры должны быть **мягкими к форме и жёсткими к сути**: «Москва»/«Moscow» засчитываются оба,
а значение enum обязано совпасть точно.

**После правок чекеров запускайте `python -m toolcalling_bench.selftest`.** Он оффлайновый и
бесплатный, гоняет ~39 синтетических случаев и проверяет, что верные ответы проходят, а типовые
ошибки отклоняются. Именно он поймал баг, из-за которого регулярка времени цепляла дату
(«17.09.2026» читалось как 17:09).

## Устройство STT/TTS

Источник данных — `stt_tts_bench/dataset.yaml`. Для STT и TTS берутся разные диапазоны строк
(`offset`), чтобы фразы для синтеза не совпадали с аудио для распознавания.

Кэш в `data/cache/` **инкрементальный**, ключ — пара «датасет+offset», без `n`. В манифесте
хранится `rows_scanned`: сколько строк датасета уже просмотрено, включая отсеянные фильтрами.
Без него докачка начиналась бы с начала и заново отбраковывала те же строки. Не добавляйте `n`
обратно в ключ — из-за этого прогоны с разным `--n` качали одни и те же записи по нескольку раз.

Второй источник — `mic_samples.py`: записи с микрофона, которые пишет панель. Одна запись
даёт пару тестов: аудио идёт в STT (эталон — введённый текст), тот же текст идёт в TTS.
Выбирается флагом `--source mic` у обоих раннеров. Браузер пересобирает запись в WAV 16 кГц
моно через `OfflineAudioContext` — провайдеры должны получать тот же формат, что и записи
из корпуса, иначе сравнение нечестное.

`add_sample` валидирует WAV сразу при сохранении и приводит `wave.Error` к `ValueError`:
эндпоинт различает их как 400 и 500, и без приведения панель показала бы голый HTTP 500.

Качество TTS меряется прогоном синтеза через STT и сравнением с исходным текстом. Проверять
нужно движками **всех** провайдеров, а не только «родного», иначе вендор получает фору на
собственном декодере. Сейчас провайдер один, поэтому метрика self-scoring и занижена —
`run_tts.py` об этом предупреждает в stderr. Появится второй STT — добавьте его в
`build_stt_checkers()`, и метрика станет честной.

WER слеп к просодии, поэтому `run_tts.py` дополнительно генерирует CSV с колонками
`naturalness_1to5` / `clarity_1to5` для оценки на слух.

Оба прогона пишут в свой каталог `results/*_samples_<ts>/` не только `.wav`, но и
`manifest.json` (эталон, расшифровки, WER, латентность). Вкладка «Прослушивание» в панели
строится только из этих манифестов — если меняете их формат, правьте и `renderAudioSet`
в `webui/index.html`. Аудио отдаётся через `/api/audio/<набор>/<путь>`; путь приходит снаружи,
поэтому он обязан проходить через `_safe_nested_file`.

Перед сравнением обе строки нормализуются (регистр, `ё→е`, пунктуация) — иначе штраф идёт
за запятые, а не за ошибки распознавания.
